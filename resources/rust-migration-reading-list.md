# Rust Migration Reading List

A curated list of the books, papers, articles, official docs, talks, podcasts and repositories behind a behavior-preserving approach to migrating Python, Go, C and C++ code to Rust.
This page only links to the original sources; it contains no copies, excerpts or transcripts. Paid books link to their publisher, plus the publisher's free sample where one exists.
Entries are grouped into three layers: **Principles** (why the method works), **Practice** (how to carry it out) and **Pitfalls** (where migrations go wrong). Each layer starts with a short **Core** set to read first, followed by **Further reading**.

Format: author or organization · title · year · access — why read.

## Principles

### Core

- **William M. McKeeman (Digital Equipment Corp.)** · [Differential Testing for Software](https://web.archive.org/web/2006id_/http://www.hpl.hp.com/hpjournal/dtj/vol10num1/vol10num1art9.pdf) (archived copy) · 1998 · `free to read` — The original statement of differential testing: run the same inputs through two implementations and treat any disagreement as a bug. This is the backbone of checking that a Rust port behaves exactly like the code it replaces. <!-- id: mckeeman-difftest -->
- **Koen Claessen & John Hughes** · [QuickCheck: A Lightweight Tool for Random Testing of Haskell Programs](https://www.cs.tufts.edu/comp/150FP/archive/john-hughes/quick.pdf) · 2000 · `free to read` — The paper that introduced property-based testing. Read it to learn how to state invariants once and let generated inputs hunt for the edge cases where old and new code diverge. <!-- id: quickcheck -->
- **Michael C. Feathers** · [Working Effectively with Legacy Code](https://www.informit.com/store/working-effectively-with-legacy-code-9780131177055) · 2004 · `paid` · [free sample chapter](https://www.informit.com/articles/article.aspx?p=359418) — The classic on pinning down existing behavior with characterization tests and finding seams to cut dependencies. It is how you build the safety net before touching any line in the source language. <!-- id: welc -->
- **Hyrum Wright** · [Hyrum's Law](https://www.hyrumslaw.com/) · c. 2016 · `free to read` — A one-paragraph law with big consequences: with enough users, every observable behavior becomes a contract. It explains why error messages, ordering and timing quirks must be inventoried and preserved, not just the documented API. <!-- id: hyrums-law -->
- **Martin Fowler** · [Strangler Fig Application](https://martinfowler.com/bliki/StranglerFigApplication.html) · 2004, rewritten 2024 · `free to read` — The canonical description of growing a replacement around a running system and retiring the old parts piece by piece. It is the default shape for an incremental Rust migration instead of a big-bang cutover. <!-- id: fowler-strangler -->
- **Joel Spolsky** · [Things You Should Never Do, Part I](https://www.joelonsoftware.com/2000/04/06/things-you-should-never-do-part-i/) · 2000 · `free to read` — The Netscape cautionary tale: old, ugly code carries years of bug fixes that a from-scratch rewrite silently throws away. A useful corrective before anyone proposes a clean-slate Rust rewrite. <!-- id: joel-never-rewrite -->

### Further reading

- **David L. Parnas** · [On the Criteria to Be Used in Decomposing Systems into Modules](https://www.cse.sc.edu/~mgv/csce590f20/ParnasCriteria.pdf) · 1972 · `free to read` — Argues that modules should hide the design decisions most likely to change. It gives a principled way to choose migration slices whose boundaries stay stable while the inside moves to Rust. <!-- id: parnas-1972 -->
- **Paul Hammant** · [Introducing Branch by Abstraction](https://paulhammant.com/blog/branch_by_abstraction.html) · 2007 · `free to read` — The original post on putting an abstraction in front of a component so old and new implementations can coexist on the main branch. It is the in-process counterpart of the strangler pattern, ideal for swapping a Python or Go module for a Rust one behind a flag. <!-- id: hammant-bba -->
- **Frederick P. Brooks, Jr.** · [No Silver Bullet: Essence and Accidents of Software Engineering](https://worrydream.com/refs/Brooks_1986_-_No_Silver_Bullet.pdf) · 1986 · `free to read` — Separates essential complexity from accidental complexity. It sets realistic expectations: a new language removes some accidents, but the problem's inherent difficulty moves to Rust with you. <!-- id: no-silver-bullet -->
- **Frederick P. Brooks, Jr.** · [The Mythical Man-Month: Essays on Software Engineering](https://www.informit.com/store/mythical-man-month-essays-on-software-engineering-anniversary-9780201835953) · 1975 (anniversary edition 1995) · `paid` · [free sample pages](https://www.informit.com/content/images/9780201835953/samplepages/0201835959.pdf) — The chapters on the second-system effect and planning to throw one away are directly relevant to rewrites. They warn against stuffing the Rust version with every feature the original never had. <!-- id: mythical-man-month -->
- **Arnon Rotem-Gal-Oz** · [Fallacies of Distributed Computing Explained](https://web.archive.org/web/2010id_/http://www.rgoarchitects.com/Files/fallacies.pdf) (archived copy) · c. 2006 · `free to read` — Walks through the eight false assumptions about networks, one at a time. Worth reading before you put a Rust service or proxy beside the old system and start splitting traffic between them. <!-- id: fallacies-explained -->
- **Theo X. Olausson, Jeevana Priya Inala, Chenglong Wang, Jianfeng Gao & Armando Solar-Lezama** · [Is Self-Repair a Silver Bullet for Code Generation?](https://arxiv.org/pdf/2306.09896) · 2023 · `free to read` — Shows that once its cost is counted, letting a model repair its own code helps less than expected, and that feedback quality is the real limit. Read it before designing an LLM-assisted translation loop. <!-- id: paper-self-repair -->
- **Titus Winters, Tom Manshreck & Hyrum Wright (eds.), Google** · [Software Engineering at Google](https://abseil.io/resources/swe-book/html/toc.html) · 2020 · `free to read` — Free online book; the chapters on Hyrum's Law, testing, deprecation and large-scale changes describe how to roll out a sweeping code change safely across a big codebase. <!-- id: swe-at-google -->
- **Nicolas Carlo** · [The Key Points of Kill It with Fire](https://understandlegacycode.com/blog/key-points-of-kill-it-with-fire) · 2021 · `free to read` — A compact summary of Marianne Bellotti's book on modernizing legacy systems. It is a quick way to absorb the advice on scoping, momentum and avoiding a full rewrite. <!-- id: kp-kill-it-with-fire -->
- **Adam Tornhill** · [Software Design X-Rays](https://pragprog.com/titles/atevol/software-design-x-rays/) · 2018 · `paid` · [free excerpt](https://media.pragprog.com/titles/atevol/safety.pdf) — Uses version-control history to find hotspots, code that is both complex and changed often. It helps rank which modules to port to Rust first and which to leave alone. <!-- id: software-design-x-rays -->

## Practice

### Core

- **PyO3 project** · [PyO3 user guide and repository](https://github.com/PyO3/pyo3) · ongoing · `free to read` — The authoritative reference for Python-Rust bindings: module layout, type conversion, the GIL, errors and object lifetimes. Almost every Python-to-Rust migration runs through it. <!-- id: pyo3 -->
- **maturin project** · [maturin user guide](https://www.maturin.rs/) · ongoing · `free to read` — The official guide to building and publishing Rust extension wheels across platforms and in CI. Read it to make sure the Rust core ships as smoothly as the pure-Python package it replaces. <!-- id: maturin-guide -->
- **Lily Mara & Joel Holmes** · [Refactoring to Rust](https://manning.com/books/refactoring-to-rust) · 2025 · `paid` · [free preview](https://livebook.manning.com/book/refactoring-to-rust) — A book-length guide to moving an existing codebase into Rust gradually through FFI and extension modules, including async Python. It is the closest thing to a full playbook for this exact job. <!-- id: refactoring-to-rust -->
- **Samuel Colvin (Pydantic)** · [Pydantic V2 Plan](https://raw.githubusercontent.com/pydantic/pydantic/4acf85da4d3e4569f2d150fffc7206e957a37010/docs/blog/pydantic-v2.md) · 2022 · `free to read` — The design plan for keeping the Python API while moving the core into Rust. It is a model for deciding what stays in the host language and what moves. <!-- id: pydantic-v2-plan -->
- **Dropbox Engineering** · [Testing Sync at Dropbox](https://dropbox.tech/infrastructure/-testing-our-new-sync-engine) · 2020 · `free to read` — How Dropbox tested its Rust sync engine with deterministic execution, randomized simulation and failing seeds turned into regression tests. A strong template for the test harness a risky migration needs. <!-- id: dropbox-testing -->
- **Hasan Ferit Eniser, Hanliang Zhang, Cristina David, Meng Wang, Maria Christakis, Brandon Paulsen, Joey Dodds & Daniel Kroening** · [Towards Translating Real-World Code with LLMs: A Study of Translating to Rust](https://arxiv.org/pdf/2405.11514) · 2024 · `free to read` — Introduces cross-language differential fuzzing to check that translated Rust matches the original's inputs and outputs. Shows how to turn behavioral equivalence into an automated check. <!-- id: paper-fluorine -->
- **Stripe (Jacqueline Xu)** · [Online Migrations at Scale](https://stripe.com/blog/online-migrations) · 2017 · `free to read` — The four-step dual-write pattern for moving data without downtime. Apply it whenever the Rust version owns its own storage or data model. <!-- id: stripe-online-migrations -->
- **Google SRE (Alec Warner & Štěpán Davidovič)** · [Canarying Releases](https://sre.google/workbook/canarying-releases/) · 2018 · `free to read` — How to choose metrics and decide pass or fail when exposing a small slice of traffic to a new build. It turns "roll out the Rust version carefully" into a concrete procedure. <!-- id: sre-canarying -->
- **Logan Cox (InfluxData)** · [Microservices to Monolith: Rebuilding Our Backend in Rust](https://www.influxdata.com/blog/rust-monolith-migration-influxdb/) · 2025 · `free to read` — A Rust proxy first takes all traffic, then endpoints move over one at a time. A practical strangler-pattern case study for services. <!-- id: influxdata-monolith -->
- **Matthias Endler (corrode)** · [Migrating from Python to Rust](https://corrode.dev/learn/migration-guides/python-to-rust/) · 2024, updated 2026 · `free to read` — A developer-oriented guide that maps Python idioms, tooling and async onto Rust equivalents. Good orientation for a team whose main experience is Python. <!-- id: corrode-py2rs -->
- **David Hewitt (PyO3 maintainer) · PyCon US** · [How Python calls land in Rust code](https://www.youtube.com/watch?v=UilujdubqVU) · 2024 · `free to read` — Talk by a PyO3 maintainer tracing what happens when Python calls into Rust. Useful for reasoning about overhead and object conversion at the boundary. <!-- id: talk-hewitt-pyo3 -->

### Further reading

- **Microsoft** · [Pragmatic Rust Guidelines](https://github.com/microsoft/rust-guidelines) · 2025 · `free to read` — Production-oriented Rust conventions, including a condensed version meant for AI coding assistants. A ready-made style baseline for the new code. <!-- id: ms-rust-guidelines -->
- **Microsoft** · [Rust Training (Rust for Python Programmers)](https://github.com/microsoft/RustTraining) · 2025 · `free to read` — Microsoft's training material; the Python track ends with migration patterns such as rewriting only the hot path. Helpful for onboarding Python developers to the target language. <!-- id: ms-rust-training -->
- **Rust Library Team** · [Rust API Guidelines](https://github.com/rust-lang/api-guidelines) · ongoing · `free to read` — The official checklist for idiomatic, stable Rust APIs. Use it when the Rust crate will itself become a public interface. <!-- id: rust-api-guidelines -->
- **David Drysdale** · [Effective Rust](https://effective-rust.com/index.html) · 2024 · `free to read` — Free online book of concrete items on types, traits, error handling and dependencies. It helps translated code read as Rust rather than as transliterated Python, Go or C++. <!-- id: effective-rust -->
- **PyO3 project** · [pyo3-async-runtimes](https://github.com/PyO3/pyo3-async-runtimes) · ongoing · `free to read` — The official bridge between Rust async runtimes and asyncio. Read it to settle who owns the event loop and how cancellation crosses the language boundary. <!-- id: pyo3-async-runtimes -->
- **Python Software Foundation** · [asyncio Event Loop](https://docs.python.org/3/library/asyncio-eventloop.html) · ongoing · `free to read` — The reference for event loops and executors, including how futures from other executors must be bridged explicitly. Essential when Rust code runs alongside asyncio. <!-- id: python-asyncio-executor -->
- **Marius Arvinte & Cory Cornelius (Intel)** · [IDEAS for TRACTOR](https://www.intel.com/content/www/us/en/security/security-practices/blogs/ideas-for-tractor.html) · 2026 · `free to read` — Describes translating C to Rust symbol by symbol, advancing only when the mixed C/Rust build still passes the whole test suite. A clear example of small, always-green migration steps. <!-- id: intel-tractor -->
- **Airbnb Engineering (Charles Covey-Brandt)** · [Accelerating Large-Scale Test Migration with LLMs](https://airbnb.tech/infrastructure/accelerating-large-scale-test-migration-with-llms/) · 2025 · `free to read` — A per-file pipeline with validation steps and retries driven by error feedback, plus a small manual tail. Shows the realistic economics of LLM-driven migration. <!-- id: airbnb-enzyme-rtl -->
- **Celal Ziftci, Stoyan Nikolov, Anna Sjövall, Bo Kim, Daniele Codecasa et al. (Google)** · [Migrating Code At Scale With LLMs At Google](https://arxiv.org/pdf/2504.09691) · 2025 · `free to read` — Generates several candidates per file, keeps one that passes and hands failures to humans rather than iterating on repairs. A useful counterpoint to repair-heavy loops. <!-- id: paper-google-id-migration -->
- **Stoyan Nikolov, Daniele Codecasa, Anna Sjovall, Maxim Tabachnyk, Satish Chandra et al. (Google)** · [How is Google Using AI for Internal Code Migrations?](https://arxiv.org/pdf/2501.06972) · 2025 · `free to read` — An overview of several internal migrations combining multiple candidates, optional repair and human review. Its main lesson is that review throughput, not generation, becomes the bottleneck. <!-- id: paper-google-ai-migrations -->
- **Amazon Web Services** · [How Amazon Q Developer transforms code](https://docs.aws.amazon.com/amazonq/latest/qdeveloper-ug/how-CT-works.html) · ongoing · `free to read` — Product documentation for a build-test-fix loop applied to Java upgrades. Useful as a contrasting design, though it reports no measured results. <!-- id: amazon-q-java-upgrade -->
- **Manish Shetty, Naman Jain, Adwait Godbole, Sanjit A. Seshia, Koushik Sen et al.** · [Syzygy: Dual Code-Test C to (safe) Rust Translation using LLMs and Dynamic Analysis](https://arxiv.org/pdf/2412.14234v2) · 2024 · `free to read` — Translates C to safe Rust by sampling several candidates first and using execution feedback only when all fail. Also shows how to translate the tests along with the code. <!-- id: paper-syzygy -->
- **Ryan Sweet (amplihack)** · [oxidizer skill in amplihack](https://github.com/rysweet/amplihack) · 2025 · `free to read` — An agent workflow for Python-to-Rust migration: close test gaps first, converge one module at a time and track a feature parity table. A concrete example of the process in automated form. <!-- id: oxidizer -->
- **Oliver Kriska** · [claude-elixir-phoenix rewrite plugin](https://github.com/oliver-kriska/claude-elixir-phoenix) · 2025 · `free to read` — An analyze, roadmap and verify pipeline for rewrites. The target is Elixir, but the staging and verification steps carry over to Rust. <!-- id: elixir-rewrite -->
- **Max Höhl · PyCon DE** · [Rustifying Python](https://www.youtube.com/watch?v=64jNiWtjCGU) · 2025 · `free to read` — Partially moving an enterprise Python application to Rust, with emphasis on observability after launch. Good for planning how to monitor the mixed system. <!-- id: talk-rustifying-python -->
- **Mike Kraus · PyData Amsterdam** · [Polishing Python with Rust](https://www.youtube.com/watch?v=Z8R9E0tleUM) · 2024 · `free to read` — A payment processor that started in Python, profiled its bottlenecks and rewrote only the critical parts with PyO3. A grounded example of targeted migration. <!-- id: talk-polishing-python -->
- **Sven-Hendrik Haase · EuroPython** · [Oxidizing the Snake: Rust and Python](https://www.youtube.com/watch?v=dZ4ETY9Mzws) · 2018 · `free to read` — Early hands-on experience combining Rust and Python. Useful history on which integration problems were already known before today's tooling. <!-- id: talk-oxidize-snake -->
- **Samuel Colvin · FOSDEM Rust devroom** · [How Pydantic V2 leverages Rust's Superpowers](https://archive.fosdem.org/2023/schedule/event/rust_how_pydantic_v2_leverages_rusts_superpowers/) · 2023 · `free to read` — The talk companion to the Pydantic V2 plan, covering how the Rust core was put together behind a Python interface. <!-- id: talk-pydantic-v2 -->
- **Cheuk Ting Ho · PyCon DE (tutorial)** · [PyO3 101: Writing Python Modules in Rust](https://www.youtube.com/watch?v=FWkCPYl_58M) · 2024 · `free to read` — A hands-on introduction to PyO3. Useful for team members who have never built a Rust extension module. <!-- id: talk-pyo3-101 -->

## Pitfalls

### Core

- **fish-shell team** · [Fish 4.0: The Fish Of Theseus](https://fishshell.com/blog/rustport/) · 2024 · `free to read` — A frank account of porting a full C++ shell to Rust incrementally: what went smoothly, where FFI and tooling hurt, and how long it really took. <!-- id: fish-theseus -->
- **Ubuntu / Launchpad bug tracker** · [Bug #2127970: rust-coreutils "date -r" ignores the reference file](https://bugs.launchpad.net/ubuntu/+source/rust-coreutils/+bug/2127970) · 2025 · `free to read` — The primary report of an option that was parsed but never wired up, which broke unattended upgrades. A sharp reminder to test every flag's behavior, not only that it is accepted. <!-- id: uutils-launchpad-bug -->
- **Marc Schoolderman (Trifecta Tech Foundation)** · [Three Years of Rusty sudo](https://trifectatech.org/blog/three-years-of-rusty-sudo/) · 2026 · `free to read` — A retrospective on sudo-rs showing that compatibility features decide adoption, and that trimming features cuts both attack surface and compatibility. Helps you choose what to leave out. <!-- id: rusty-sudo-3y -->
- **Ali Reza Ibrahimzada, Kaiyao Ke, Mrigank Pawagi, Muhammad Salman Abid, Rangeet Pan et al.** · [AlphaTrans: A Neuro-Symbolic Compositional Approach for Repository-Level Code Translation and Validation](https://arxiv.org/pdf/2410.24117v5) · 2024 · `free to read` — Repository-level translation where nearly all output compiles but only a minority is functionally equivalent. The clearest evidence that "it builds" says little about "it behaves the same". <!-- id: paper-alphatrans -->
- **Waleed Khan** · [Incrementally Porting a Small Python Project to Rust](https://blog.waleedkhan.name/port-python-to-rust/) · 2021 · `free to read` — Lessons from moving git-branchless from Python to Rust module by module, including the friction of calling back and forth at runtime. <!-- id: git-branchless-port -->

### Further reading

- **Sujay Jayakar (Dropbox)** · [Rewriting the Heart of Our Sync Engine](https://dropbox.tech/infrastructure/rewriting-the-heart-of-our-sync-engine) · 2020 · `free to read` — Why Dropbox rewrote its sync engine in Rust: the old data model's problems only surfaced at scale. Shows what a rewrite must fix beyond the language itself. <!-- id: dropbox-nucleus -->
- **uutils project** · [Rust Coreutils 0.12.0 release notes](https://github.com/uutils/coreutils/releases/tag/0.12.0) · 2026 · `free to read` — Uses the GNU test suite as the referee and lists the remaining failures openly. A model for measuring compatibility with an external oracle. <!-- id: uutils-0.12 -->
- **Michael Larabel (Phoronix)** · [Ubuntu 25.10 Unattended Upgrades Broken Due To Rust Coreutils Bug](https://www.phoronix.com/news/Ubuntu-25.10-Broken-Upgrade) · 2025 · `free to read` — News coverage of the date -r regression and its downstream impact. Read with the Launchpad report to see how one unimplemented flag escalates. <!-- id: uutils-date-bug -->
- **Jelmer Vernooij** · [Porting Python Projects to Rust](https://www.jelmer.uk/port-py-to-rust.html) · 2023 · `free to read` — Argues that an all-at-once idiomatic rewrite is far slower than iterative porting, and proposes splitting each subsystem into a pure Rust crate plus a bindings crate. <!-- id: jelmer-port-py -->
- **Grab Engineering** · [Counter Service: How We Rewrote It in Rust](https://engineering.grab.com/counter-service-how-we-rewrote-it-in-rust) · 2025 · `free to read` — A Go-to-Rust service rewrite with honest costs: missing internal libraries, library selection and replacing a Redis client mid-project. <!-- id: grab-counter -->
- **Hanliang Zhang, Cristina David, Meng Wang, Brandon Paulsen & Daniel Kroening (Amazon)** · [Scalable, Validated Code Translation of Entire Projects using Large Language Models](https://cdn.amazon.science/0e/ab/c10459dd4013a7c02f09b8c96f3f/scalable-validated-code-translation-of-entire-projects-using-large-language-models.pdf) · 2025 · `free to read` — Whole-project Go-to-Rust translation (PLDI 2025). Reports models getting stuck in repair loops and argues for preventing errors before generation. <!-- id: paper-oxidizer-go-rust -->
- **Yubo Bai & Tapti Palit** · [RustAssure: Differential Symbolic Testing for LLM-Transpiled C-to-Rust Code](https://arxiv.org/pdf/2510.07604) · 2025 · `free to read` — Finds semantic bugs in C-to-Rust translations that differential fuzzing missed. A reason to add symbolic or targeted checks on top of random inputs. <!-- id: paper-rustassure -->
- **Guangsheng Ou, Mingwei Liu, Yuxuan Chen, Yanlin Wang, Xin Peng et al.** · [RustRepoTrans: Repository-level Code Translation Benchmark Targeting Rust](https://arxiv.org/pdf/2411.13990) · 2024 · `free to read` — A benchmark and failure taxonomy for repository-level translation to Rust. Useful for anticipating where an LLM-assisted port will break. <!-- id: paper-rustrepotrans -->
- **Cian Butler (Cloudsmith) with Matthias Endler · Rust in Production podcast** · [Cloudsmith (S06E01)](https://corrode.dev/podcast/s06e01-cloudsmith/) · 2026 · `free to read` — Bringing Rust extensions into a Python monolith, the edge cases nobody predicted, and a roadmap that ran longer than planned. <!-- id: podcast-cloudsmith -->
